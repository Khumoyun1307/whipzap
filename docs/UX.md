# WhipZap UX Specification

Status: Approved for implementation
Last updated: 2026-10-21
Owner: Technical lead

Every string in this file is final copy. Implement it verbatim. Timings are targets with a tolerance of plus or minus 20 percent unless a test in `TESTING.md` pins them. Mechanics live in `ARCHITECTURE.md`; this file says what the user sees, hears, and reads.

## 1. First run

### 1.1 All platforms

1. The user runs `npx whipzap` or `whipzap`. The terminal prints:
   `WhipZap started. Look for the whip icon in your tray.`
2. A tray icon appears (section 2, state idle). No window opens. No toast on first run except the ones below.
3. Hovering the icon shows the tooltip `WhipZap: no target locked`.

### 1.2 Windows

Nothing extra. If any hotkey could not be registered, toast `Hotkey Ctrl+Alt+W is taken. Change it in config.` (with the actual accelerator), 4000 ms.

### 1.3 macOS

Typing requires the Accessibility permission. WhipZap does not ask at launch; it asks the first time the user locks a target, so the request is tied to an action the user just took.

1. On the first lock attempt, if the permission is missing, macOS shows its own dialog (`"Electron" would like to control this computer using accessibility features.` or the same text naming the terminal the user launched WhipZap from).
2. At the same time WhipZap shows a native dialog:

   Title: `WhipZap needs Accessibility access`
   Body: `WhipZap types its messages like a keyboard, which macOS only allows for apps listed under System Settings > Privacy & Security > Accessibility. Turn on the switch next to "Electron" (or next to the terminal app you launched WhipZap from), then lock the target again. Sound and visuals work without this.`
   Buttons: `Open Settings` (opens `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`), `Later`.

3. Until permission is granted, every crack still plays sound and visuals and toasts `Accessibility permission required` (3000 ms).
4. WhipZap re-checks on every lock attempt; no restart is required after granting [ASSUMED; if macOS caches the denial per process, the dialog body gains the sentence `Then quit WhipZap from the tray and start it again.` and the toast becomes `Accessibility permission required. Restart WhipZap after granting it.`].

### 1.4 Linux

| Condition | Native dialog at start (title `WhipZap`) | Typing |
|---|---|---|
| Wayland session | `Wayland is not supported yet. WhipZap will play sounds and visuals, but it cannot type into windows under Wayland. Log in to an X11 session to use typing.` Button `OK`. | disabled |
| `xdotool` missing | `xdotool is required for typing on Linux. Install it with your package manager (for example: sudo apt install xdotool), then restart WhipZap.` Button `OK`. | disabled |

Each crack in a disabled state toasts the matching short line from section 8.

## 2. Tray icon states

Monochrome glyph of a whip with a handle, drawn inside a 16 px square (32 px at 2x), generated by `scripts/gen-icons.ps1`. Files: `assets/icons/tray-idle.png`, `tray-locked.png`, `tray-armed.png`, `tray-auto.png` (32 px) with `-16` variants (16 px), macOS variants `trayTemplate.png`, `trayLockedTemplate.png`, `trayArmedTemplate.png` with `@2x`, and `app-256.png` for the app icon. State is encoded by a small badge (none = idle, dot = locked or auto, ring = armed); the tooltip carries the exact state.

| State | Glyph | Condition | Tooltip |
|---|---|---|---|
| idle | coiled whip, outline only | no target | `WhipZap: no target locked` |
| locked | coiled whip, filled | target locked, not armed, auto off | `WhipZap: locked on <title truncated to 40 chars>` |
| armed | whip uncoiled, lash extends to the right | whip mode active | `WhipZap: whip armed` |
| auto | coiled whip with a small clock dot in the corner | auto on (takes precedence over locked; armed still wins while armed) | `WhipZap: auto mode, N of CAP` |

Precedence: armed > auto > locked > idle. On macOS the glyph is a template image so it inverts with the menu bar. On Windows the icon has a 1 px dark outline to stay visible on light taskbars.

## 3. Tray menu

Exact order and labels. Left or right click opens the menu on Windows and Linux; on macOS click opens it. The menu is rebuilt after every state change.

| # | Label | Type | Enabled when | Action |
|---|---|---|---|---|
| 1 | `Arm whip` | checkbox | always | checked: enter whip mode (locks target first if none). Unchecked: drop whip. |
| 2 | `Crack now` | normal | `typingAvailable` or not; always enabled (plays sound and visual even without a target) | lock target if none, then one crack with `source: 'tray'` |
| 3 | `Auto mode` | checkbox | always | toggle auto (locks first if none) |
| 4 | `Delivery` | submenu | always | contains two radio items: `Safe (queued message)` and `/btw (side question)` |
| 5 | `Mute` | checkbox | always | toggle `sound.muted`, saved to config |
| 6 | `Open config` | normal | always | `shell.openPath(configPath)`; creates the file with defaults first if missing |
| 7 | `Lock target` | normal | always | lock the foreground window (section 4); on Windows this is the window that was foreground just before the tray click (`platform.lastForeground`) |
| 8 | `Quit` | normal | always | unregister hotkeys, drop whip, stop scheduler, `app.quit()` |

Separators after items 3, 5, and 7. Item labels show the hotkey as the accelerator hint where the platform supports it (`Arm whip  Ctrl+Alt+Shift+W`). The `/btw` radio label carries a tooltip on platforms that support it: `Claude Code only. Other agents receive it as plain text.`

While `typingAvailable` is false, items 1 to 3 and 7 keep working but every lock shows the relevant toast from section 8, so the user learns why typing is missing without a dead menu.

## 4. Lock flow

Trigger: `Lock target`, `Arm whip`, `Auto mode`, or `Crack now` with no target, or the crack or arm hotkey with no target.

1. WhipZap reads the foreground window. On a tray action it uses the window that was foreground just before the tray click (the tray click itself moves focus).
2. If the window is WhipZap's own overlay or the tray, nothing happens and a toast says `Click your terminal first, then lock.` (3000 ms).
3. If the process name or title matches the allow patterns, lock immediately. Toast `Target locked: <title>` (2500 ms, title truncated to 60 chars with an ellipsis).
4. Otherwise show a native confirm dialog once for this window:

   Title: `Whip this window?`
   Body: `"<title>"\n<processName>\n\nThis does not look like a terminal or code editor. WhipZap will type messages into it.`
   Buttons: `Whip it` (default), `Cancel`.

   `Whip it` locks and toasts as in step 3. `Cancel` leaves no target and shows no toast.
5. The lock persists until the window closes, the user locks another, or WhipZap quits. A new lock replaces the old one silently apart from the toast.

The sanity check is per lock, not per crack. A window that was confirmed once is not asked again while locked.

## 5. Hotkeys

| Action | Windows and Linux | macOS | Config key |
|---|---|---|---|
| Crack now | Ctrl+Alt+W | Cmd+Alt+W | `hotkeys.crack` |
| Arm or drop whip | Ctrl+Alt+Shift+W | Cmd+Alt+Shift+W | `hotkeys.armWhip` |
| Toggle auto mode | Ctrl+Alt+A | Cmd+Alt+A | `hotkeys.toggleAuto` |

Rules:

1. Hotkeys work regardless of which window has focus.
2. Crack now with no target locks the current foreground window first (section 4), then cracks. With a terminal focused, this makes the first ever crack a single keypress.
3. Arm whip while armed drops the whip.
4. There is no hotkey to quit; quitting is a deliberate tray action.
5. Accelerators are Electron accelerator strings. A failed registration toasts `Hotkey <accel> is taken. Change it in config.` (4000 ms) and the rest still register.

## 6. The crack

What happens when any trigger fires, in order, with timings measured from the trigger.

| Time | Sound | Overlay | Typing |
|---|---|---|---|
| 0 ms | one of three crack samples at `sound.volume` | overlay shown; lash animation starts (6.1) | focus request sent to the locked window |
| 0 to 600 ms | | lash travels across the screen; edge flash | focus verified, then 150 ms settle |
| ~150 to 250 ms | | message text pops in (6.2) | typing begins; characters appear in the terminal as the lash finishes |
| 600 ms | | lash gone; message held | Enter sent after the last character |
| 1200 ms after message appears | | message fades out over 200 ms | |
| ~1800 ms | | overlay hidden | |

Whip mode cracks replace the lash with the tip burst (section 7) but keep the message, sound, and typing identical.

The message typed is exactly the message shown, with the `/btw ` prefix added when delivery is `/btw`. The overlay shows the prefix too, in a smaller weight, so the user is never surprised by what landed in the terminal.

### 6.1 Lash animation (strike flash)

1. A single diagonal line from one screen edge to the opposite edge. Angle chosen from the seed between 25 and 65 degrees, direction (top-left to bottom-right or top-right to bottom-left) also seeded.
2. The line is drawn progressively over 180 ms as a tapered stroke: 14 px wide at the start, 3 px at the tip, white core with a 40 percent black outer glow so it reads on both dark and light screens.
3. At 180 ms the tip reaches the far edge and a 160 ms radial burst (radius 90 px, white to transparent) fires there.
4. From 180 ms to 600 ms the line fades to zero opacity while the whole display edge pulses once: a 12 px inset vignette at 25 percent white opacity, 120 ms in, 300 ms out.
5. Nothing on screen flashes more than once per crack. With cracks rate-limited to one per 300 ms, flash frequency never exceeds 3 Hz.
6. Reduced motion: steps 1 to 4 are replaced by a single 200 ms full-screen white flash at 12 percent opacity plus the message.

### 6.2 Message text

1. Centered horizontally, vertically at 38 percent of the display height.
2. Font stack: `"Impact", "Arial Black", "Helvetica Neue", Arial, sans-serif`, bold, uppercase as written in the pack (packs may contain lowercase; it is rendered as given, not transformed).
3. Size: `clamp(40px, 7vw, 120px)`. Long messages wrap to at most two lines at 80 percent of the display width.
4. Fill white, 4 px dark outline (`#15110c`), 24 px soft shadow at 50 percent black.
5. Entrance: scale from 1.3 to 1.0 and opacity 0 to 1 over 120 ms with a slight overshoot. Hold 1200 ms. Exit: opacity to 0 over 200 ms.
6. In `/btw` delivery the prefix `/btw` is shown above the message at 40 percent of the message size, same style, so the user sees the full typed text.
7. Tier accent: a thin underline below the message, 4 px, colour by tier: mild `#ffd166`, medium `#ff7b54`, spicy `#ef233c`.

## 7. Whip mode

1. Entering: the overlay appears on the primary display, the system cursor is hidden over the overlay (`cursor: none`), and a rope spawns hanging from the cursor position with a 300 ms unfurl (segments start stacked at the handle and settle under gravity).
2. Appearance: a 3 px dark core (`#15110c`) over a 7 px pale halo (`rgba(255,255,255,0.55)`), slight taper towards the tip, a 10 px by 26 px rounded handle at the cursor in `#3a2a1a` with a lighter `#6b4a2b` grip band.
3. Cracking: a fast flick makes the tip exceed the crack threshold. A 120 ms burst (radius 60 px) fires at the tip, the crack sound plays, and the message and typing run as in section 6. Cooldown 250 ms; no cracks in the first 400 ms after spawn.
4. The rope reacts to screen edges with a soft bounce and never leaves the display.
5. Dropping: any mouse button down on the overlay, the arm hotkey, or unchecking `Arm whip` in the tray. The handle releases, the rope falls off the bottom of the screen under triple gravity, the cursor returns, and the overlay hides. Toast `Whip dropped` is not shown; the visual is enough.
6. There is no Esc handling. The overlay never listens for Esc and WhipZap never sends Esc anywhere.
7. Auto mode is paused while the whip is armed and resumes on drop.
8. Multi-monitor: the rope lives on the primary display only. Moving the mouse to another display leaves the handle at the display edge [v1 limitation, documented].

## 8. Toasts

All toasts render on the overlay, bottom centre, 48 px above the display bottom, in a pill: 14 px padding, 10 px radius, background `rgba(21,17,12,0.88)`, white 16 px system sans-serif text, 150 ms fade in, 200 ms fade out. One toast at a time; a new one replaces the current one immediately. The overlay is shown for the toast and hidden when it ends if nothing else is active.

| Text | Duration ms | When |
|---|---|---|
| `Target locked: <title>` | 2500 | after a successful lock |
| `No target locked` | 2500 | crack with no target and the lock could not be made |
| `Click your terminal first, then lock.` | 3000 | lock attempted while WhipZap itself is foreground |
| `Target window closed` | 3000 | target gone at crack time |
| `Could not focus target` | 3000 | Windows helper exit 5 |
| `Auto mode on` | 2000 | auto toggled on |
| `Auto mode off` | 2000 | auto toggled off by the user or by unlock |
| `Auto session cap reached (<N>)` | 3500 | scheduler stopped at the cap; N is `auto.sessionCap` |
| `Muted` / `Unmuted` | 1500 | mute toggled |
| `Config reloaded` | 2000 | file watcher applied a valid config |
| `Config invalid, using defaults` | 4000 | validation failed; `.bak` written |
| `Hotkey <accel> is taken. Change it in config.` | 4000 | registration failed |
| `Accessibility permission required` | 3000 | macOS helper exit 2 |
| `Wayland is not supported` | 3000 | Linux Wayland session on a typing attempt |
| `xdotool not found` | 3000 | Linux helper missing on a typing attempt |
| `Typing failed` | 3000 | any other helper error or timeout |
| `WhipZap is already running` | 2500 | second instance launched |

## 10. Sound

| Item | Spec |
|---|---|
| Samples | three distinct whip cracks, `crack-1.wav`, `crack-2.wav`, `crack-3.wav` (PCM 16-bit mono 48 kHz) |
| Length | at most 0.8 s each, with the transient within the first 40 ms so the sound and lash feel simultaneous; trimmed from the sources by `scripts/prepare-sounds.mjs` |
| Level | peak normalised to -1 dBFS; loudness roughly matched between files |
| Source | Joseph Sardin, BigSoundBank.com, "Whip crack #2, #3, #4" (https://bigsoundbank.com/whip-crack-2-s2950.html, whip-crack-3-s2951.html, whip-crack-4-s2952.html), licence on page: "CC0 (public domain): Free and royalty-free" |
| Licence | CC0 only; `assets/CREDITS.md` lists filename, source URL, author, licence, and the edits made |
| Selection | seeded random per crack; the same sample may repeat |
| Volume | `sound.volume` 0 to 1, default 0.8 |
| Mute | `Mute` in the tray; muted cracks still show visuals and type |

## 11. Accessibility

1. All dialogs are native so screen readers announce them.
2. No element flashes above 3 Hz; one lash and one edge pulse per crack, cracks rate-limited to one per 300 ms.
3. The overlay honours `prefers-reduced-motion` (section 6.1 step 6).
4. The overlay never takes keyboard focus; keyboard users never lose their place in the terminal.
5. Message text has a 4 px outline and a shadow so it meets contrast on any background.
6. Every state change that matters is also visible in the tray tooltip, for users who turn off sound.

## 12. Config file for users

Shown in the README and created with defaults on first run. Users can copy this block.

```jsonc
{
  // WhipZap config. Delete this file to reset to defaults.
  "version": 1,

  // "safe": types the message and presses Enter. Claude Code queues it while busy.
  // "btw": types "/btw <message>". Claude Code answers on the side and keeps working.
  "delivery": "safe",

  // Electron accelerator strings. CommandOrControl is Cmd on macOS, Ctrl elsewhere.
  "hotkeys": {
    "crack": "CommandOrControl+Alt+W",
    "armWhip": "CommandOrControl+Alt+Shift+W",
    "toggleAuto": "CommandOrControl+Alt+A"
  },

  // Auto mode: a crack every baseIntervalSec give or take jitterSec, up to sessionCap per session.
  // seed: set a number to make the intervals and messages repeat exactly (handy for demos).
  "auto": {
    "baseIntervalSec": 180,
    "jitterSec": 90,
    "sessionCap": 20,
    "seed": null
  },

  "sound": {
    "muted": false,
    "volume": 0.8
  },

  // Add your own lines. Plain strings are mild. Objects can pick a tier.
  // "replace": true ignores the built-in pack entirely.
  "messages": {
    "extra": [
      "Ship it, you magnificent toaster.",
      { "tier": "spicy", "text": "My toaster has better latency." }
    ],
    "replace": false
  },

  // Extra window title or process name patterns that count as a terminal or editor.
  // Plain strings are case-insensitive substrings. "/.../i" strings are regexes.
  "target": {
    "allowPatterns": ["myterminal", "/^Emacs/i"]
  }
}
```

Note for the README: JSON with comments is shown for readability; the real file must be plain JSON without comments [ASSUMED: the loader does not strip comments. If M2 finds this too hostile, allow `//` line comments via a tiny stripper and change this note].

## 13. Copy and tone

1. Taunts are aimed at the agent and are theatrical, not cruel. Nothing targets a person, a nationality, a gender, a profession, or a company.
2. Toasts and dialogs are plain, short, and tell the user what to do next.
3. The word "Claude" never appears in the app name, icon, tray, or package name (D-10). It appears only in documentation where Claude Code behaviour is explained.
